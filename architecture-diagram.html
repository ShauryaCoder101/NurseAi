Architecture Overview

NurseAI

AI-powered Clinical Decision Support System for frontline healthcare in rural West Bengal — built on a 3-node architecture with multi-model AI consensus.

🏗 Three-Node Architecture
📱

Node 1 — Mobile App

React Native (Expo) • Android
  • Voice recording of patient interviews
  • Multi-segment audio capture (dual-audio)
  • Patient registration & ID management
  • Real-time AI clinical suggestions
  • Follow-up Q&A with AI
  • Missing vitals data input
  • Patient history timeline view
  • OTP-based nurse authentication
  • Offline-first with smart retry queues
⚙️

Node 2 — Backend Server

Node.js (Express) • AWS Elastic Beanstalk
  • RESTful API with JWT authentication
  • 3-stage AI pipeline orchestrator
  • Multi-LLM consensus engine (NLP merge)
  • Rate limiting & exponential backoff
  • Audio file handling (Supabase Storage)
  • Longitudinal patient data aggregation
  • AI reasoning audit trail logging
  • Doctor verification portal (SSR)
  • Benchmarking data pipeline
  • Auto-generated patient HTML records
🧠

Node 3 — AI Engine

Gemini 3.1 Pro • Multi-Model Fleet
  • Direct audio-to-clinical-output (no ASR)
  • 3-stage clinical prompting system
  • RAG grounded on textbook & STG knowledge
  • Structured reasoning extraction (XAI)
  • Longitudinal history context injection
  • Automatic model fallback (3.1 → 2.5 Pro → Flash)
  • Multi-model benchmarking (GPT-4o, Grok-3, Claude, DeepSeek)
  • Bilingual output (English + Bengali)

🛡️ AI Safety Guardrails — Reducing Hallucinations

📖
RAG: Textbook-Grounded Knowledge — Prompts mandate verification against STGs (NHM, ICMR, WHO, WBHFW) before any recommendation. Search-and-Extract protocol requires source attribution.
🚫
Zero-Tolerance Rule — If search results are vague or dosage not found, the AI must state "consult a supervising doctor" rather than hallucinate a value.
🔍
Ghost Citation Prohibition — AI cannot reference any guideline (e.g., "Per WBHFW…") unless actively retrieved and verified in the current session.
🗳️
Multi-Model Consensus (NLP Merge) — 3 independent LLMs generate responses; entity-level semantic deduplication + majority voting ensures only 2/3 agreement passes.
📊
Source Validation Footer — Every prescription output includes a mandatory footer: Guideline Used, Last Verified Date, and Confidence Level (High/Medium/Low).
👨‍⚕️
Human-in-the-Loop — Doctor verification portal enables expert review of every AI output. Flagging system for suspect outputs with mandatory re-evaluation.
🧾
Explainable AI (XAI) Audit — Every response includes structured reasoning logs: input summary → step-by-step clinical rationale → output summary, stored for review.
📋
Longitudinal Context Injection — Full patient visit history is injected into every AI call, preventing contradictory or duplicative recommendations across visits.
✨ Key System Features
📖

RAG — Textbook Knowledge Base

Retrieval-Augmented Generation grounded on GoI Standard Treatment Guidelines, ICMR protocols, WHO guidelines, and West Bengal state health directives. Every recommendation is evidence-anchored.

Knowledge Layer
📚

Longitudinal Patient Memory

Every past visit — diagnosis, prescription, follow-up — is aggregated into a chronological patient history and injected as context for every new AI call. The system remembers.

Patient Context
🗳️

Multi-Model Consensus Engine

NLP Merge Pipeline: 3 LLMs independently generate clinical output → entity extraction → semantic deduplication → majority voting → synthesized consensus response.

Safety Layer
🧾

Explainable AI (XAI)

Structured reasoning extraction with step-by-step clinical rationale. Each AI decision is decomposed into: input → reasoning steps → conclusion, stored for audit.

Transparency
🔊

Direct Audio Processing

Gemini processes raw audio natively — no separate ASR/STT step. This reduces error propagation from transcription mistakes and captures tonal/contextual nuances.

Innovation
🌐

Bilingual Clinical Output

English for clinical sections, Bengali vernacular for patient education. Includes colloquial symptom descriptors (e.g., "Buk-e-bhaar" for chest heaviness) for local accessibility.

Accessibility
🚨

Triage & Red Flag Detection

Automatic identification of life-threatening conditions requiring immediate "Stabilize and Transfer." Contextualised to West Bengal endemics: Malaria, Dengue, Scrub Typhus, JE.

Patient Safety
👨‍⚕️

Doctor Verification Portal

Server-rendered web portal for supervising physicians to review AI outputs, verify diagnoses, grade prescription quality, and provide expert feedback with verification stamps.

Quality Assurance
📄

Auto-Generated Patient Records

Dynamic HTML patient records auto-generated after every visit — combining demographics, vitals, AI outputs, doctor verifications, and follow-up history into printable reports.
